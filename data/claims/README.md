# Manufacturer claims — manual gold standard

Hand-extracted quantitative claims from official manufacturer datasheets.
This is the **gold standard** the later LLM-extraction agents will be evaluated
against — every value here was read from the PDF by a human, page number
recorded. No LLM was involved in producing these files.

One YAML file per datasheet document. PDFs live in `datasheets/` (gitignored,
re-downloadable; URLs + retrieval dates in `../README.md`).

## Format

```yaml
cell_model: <exact commercial model, matches cell_metadata.py / KG Cell.model>
manufacturer: <name>
source_document: <pdf filename in datasheets/>
source_url: <where the PDF was retrieved>
retrieved: <YYYY-MM-DD>
claims:
  - property: <snake_case property id, see vocabulary below>
    value: <number, or [lo, hi] for a range>
    unit: <Ah | mAh | V | A | C | cycles | pct | degC | ...>
    page: <page number in the PDF>
    stated_conditions:            # what makes the claim comparable to measurements
      text: <verbatim/near-verbatim condition wording from the datasheet;
             "unspecified" if the datasheet states none — that omission is
             itself a finding and is recorded explicitly>
      temperature_c: <parsed, if stated>
      charge_c_rate | charge_current_a: <parsed, if stated>
      discharge_c_rate | discharge_current_a: <parsed, if stated>
      dod_pct: <parsed, if stated>
      end_condition: <e.g. "capacity >= 70% of initial", if stated>
    notes: <optional free text — reading caveats, graph-derived values, etc.>
```

## Rules

- Record what the datasheet SAYS, not what is plausible. Ranges as `[lo, hi]`.
- Values read off a graph (not a printed number) get `notes: "read from graph"`
  and conservative rounding.
- A cycle-life claim without stated conditions gets
  `stated_conditions: {text: unspecified}` — never invent conditions.
- Every claim carries `page` so it can be re-verified against the PDF.
